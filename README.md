# Plata — контроллер усилия на STM32F103C8T6

Проект для удержания заданного усилия (100…600 г) на левой или правой стороне
платформы. Каждая сторона имеет свой тензодатчик YZC-133 + NAU7802 и свой
шаговый двигатель NEMA17 + MKS SERVO42D по RS485.

Текущий статус: **Шаги 1–3 выполнены, добавлено и проверено экспериментальное
демо «тензодатчик → каретка»**.
Версия `0.5-step3`, сборка без ошибок и предупреждений.
В прошивку временно зашита калибровка: `tare=-67471`, `counts/g=1116`.

Подробная архитектура и план: `STEP0_SPEC.md`.  
Калибровка тензодатчика: `CALIBRATION.md`.  
Список команд: `COMMANDS.md`.  
Подробный разбор кода: `CODE_OVERVIEW.md`.

## Текущий результат

Калибровка по поверенной гире 200 г:

```text
T1 (без нагрузки):  tare raw = -67 471
CAL1 200:           counts/g = 1116
R1:                 raw = 156 473, F = 200.7 g
```

Пакет сырых отсчётов `B1 10` при той же гире:

```text
189.1 … 213.9 g
range ≈ 24.8 g
```

`R1` (усреднение 8 отсчётов) показывает 200.7 г — хорошо. Сырые одиночные
отсчёты пока шумные; для контура нужен медианный фильтр 3–5.

- Тактирование 72 МГц через HSE 8 МГц + PLL работает.
- NAU7802 на I2C1 инициализируется, ревизия `0x0F`.
- Калибровка сейчас хранится в RAM и пропадёт после сброса.
- Второй NAU7802 на I2C2 пока не найден.
- MKS SERVO42D на адресе 1 отвечает.
- Мотор проверен: `JOG +1 RPM` и `JOG -1 RPM` по 500 мс, после движения
  связь остаётся ONLINE. Причина прежних OFFLINE — лишний активный ответ
  MKS в USART2; добавлена очистка RX и отключены active-ответы (`8C 01 00`).
- Связь по COM5 проверена: плата отвечает на `STATUS`.

### Демо «нажал → поехал, отпустил → вернулся»

Проверено на стенде:

- home — дальний край, 258623 counts (6.3k на экране MKS);
- far — ближний край, 0; при нажатии каретка едет к 0
  (counts уменьшаются), при отпускании возвращается к 258623;
- 200 г дают ~27 RPM, 600 г — 90 RPM (`GAIN 0.16`, `MAXRPM 90`);
- полный ход ~189000 counts: вперёд при 200 г ~3 с, возврат 20 RPM ~4 с;
- запасы `MARGIN 15000/55000` counts у краёв;
- шум датчика ±20 г больше не двигает каретку: медиана 5 отсчётов
  и порог `DEADBAND 30`;
- перегрузка выше 900 г останавливает мотор, но демо остаётся
  включённым и продолжает после отпускания.

Текущая конфигурация демо (хранится в RAM):

```text
home=258623  far=0  margin=15000/55000
DIR=1  GAIN=0.16  MAXRPM=90  RETURN=20
DEADBAND=30  RELEASE=15
```

### Запуск одной командой

```text
AUTO
```

`AUTO` (алиасы `SETUP`, `AUTODEMO`) выполняет `INIT` + `T1` + `HOME` +
настройку пределов/скоростей + `DEMO 1`. После каждой тары ставит
известный коэффициент `1116 counts/g`; другой можно задать командой
`COEF <counts/g>`. Занимает до ~30 с на homing и ещё ~6 с на возврат
к home. Во время выполнения не трогай датчик.

## Как смотреть вывод

Вывод идёт через **USART1 → SP3485 №1 → внешний RS485 A/B**, а не через
USB-разъём STM32 и не через ST-Link.

- USB-RS485 адаптер: A/B к внешнему RS485 платы, общий GND.
- Терминал: **115200, 8N1, без flow control**.
- В PuTTY: `Terminal → Local echo → Force on`, иначе вводимые символы не видны.
- Порт сейчас: **COM5** (FTDI USB Serial Port).

Если COM5 занят — значит, его уже держит другой экземпляр PuTTY. Один COM-порт
может быть открыт только одной программой.

Последовательность работы с тензодатчиком:

```text
INIT
T1
(положить известный вес, например 500 г)
CAL1 500
R1
B1 10
STREAM 1 200
STREAM 0
```

Быстрый поток только с весом:

```text
RATE 320
FAST 1
...
FAST 0
```

В режиме `FAST` в терминал идёт только:

```text
200.7
201.1
199.8
```

Без `STREAM:`, `F=` и raw. Измеренная частота на текущей прошивке —
около **318 Гц** (номинал NAU7802 320 SPS; точность зависит от внутреннего
генератора). `FAST` использует одиночные отсчёты, поэтому шум выше, чем
у `STREAM` с медианой.

Безопасная последовательность проверки мотора:

```text
EN 0
MODE
EN 1
JOG 2 1000
STOP
```

`MODE` меняет режим драйвера постоянно. `JOG` выполнять только если механизм
безопасно двигается и нет упора.

## Важные замечания

- Внешний RS485 и RS485 моторов — разные SP3485, каждый со своим DE.
- NAU7802 имеют фиксированный адрес `0x2A`, поэтому две шины I2C.
- Питание NAU7802 — 3.3 В, I2C STM32 тоже 3.3 В. 5 В на плату без
  level shifter не подавать. YZC-133 — пассивный мост, 3.3/5 В допустимы,
  но при 5 В нужна перекалибровка и растёт нагрев/шум.
- Второй датчик сейчас не найден. Если он не подключён — это нормально;
  после подключения отправить `SCAN`.
- Первый NAU7802: ревизия `0x0F`, тара и калибровка по 200 г выполнены.
  Калибровка хранится в RAM и сбрасывается при перезагрузке.
- Мотор после сброса уже enabled. Если он не нужен — отправить `EN 0`.
- Для реальной работы добавить концевые выключатели и аппаратный e-stop.
- Питание платы и моторов включать раздельно, общий GND обязателен.
